# Почасовой прогноз велопроката в Сеуле

Сравниваем три набора входов на [SeoulBikeData.csv](../SeoulBikeData.csv). В каждой схеме разделения выбираем модель по валидационной RMSE. Затем измеряем метрики победителя на отложенных часах этой схемы.

## Структура проекта

| Каталог | Ответственность |
|---|---|
| [data/](data/) | Загрузка CSV, признаки и разбиения |
| [validation/](validation/) | Модели, пайплайны и проверка конфигураций на валидации |
| [evaluation/](evaluation/) | Финальный прогон победителей на отложенных часах |
| [reports/](reports/) | Сборка HTML-отчёта и шаблон |
| [streamlit_app/](streamlit_app/) | Форма и прогноз сохранённой моделью |
| [experiments/](experiments/) | Дополнительные эксперименты, в том числе веса при обучении бустинга |
| [results/](results/) | CSV с замерами, отчёт и модели |

В корне `lshvetsov` лежат документация, настройки проекта и [paths.py](paths.py) с общими путями к датасету и результатам.

## Запуск эксперимента

Из корня репозитория выполните команды через uv. Версии зависимостей закреплены в `uv.lock`.

```bash
uv run --project lshvetsov --locked --python 3.12 -m lshvetsov.validation.train
uv run --project lshvetsov --locked --python 3.12 -m lshvetsov.evaluation.finalize
uv run --project lshvetsov --locked --python 3.12 -m lshvetsov.reports.report
```

| Схема | Валидация | Тест |
|---|---|---|
| Временные фолды | Окна июля–октября, каждое после своего обучающего периода. Октябрьское окно заканчивается перед тестом. | Последние 10% открытых часов. |
| Случайное 80/10/10 внутри месяца | Случайные 10% открытых часов внутри каждого из 12 месяцев. | Ещё 10% из каждого месяца, заранее отложенные. |
| Случайное 80/10/10 по году | Случайные 10% открытых часов всего года. | Ещё 10% открытых часов, заранее отложенные. |

- `train` фиксирует разбиения и обучает конфигурации. В случайных схемах сохраняет обученных победителей на валидации. Точные назначения часов лежат в [split_membership.csv](results/split_membership.csv), а метрики всех конфигураций — в CSV с префиксом `validation_`.
- `finalize` берёт победителя по валидационной RMSE внутри каждой пары схемы и сценария. Для фолдов обучает модель с выбранными настройками на всей истории до теста. Для 80/10/10 использует сохранённую модель, обученную на соответствующих 80%. Сохраняет девять моделей и [манифест](results/models/manifest.json).
- [test_metrics.csv](results/test_metrics.csv) содержит итоговые тестовые метрики девяти победителей и заранее заданной почасовой медианы в каждой схеме. В [test_predictions.csv](results/test_predictions.csv) лежат факт и прогнозы победителей и ориентира на каждом тестовом часе.
- `report` собирает автономный `results/report.html` из CSV. В нём есть методология, финалисты, диагностика пиков и таблицы валидации. Отчёт можно собрать из сохранённых CSV, а для запуска формы нужны локальные файлы Joblib.

Для другого каталога передайте `--output-dir` команде `train`, а `--results-dir` — командам `finalize` и `report`. При воспроизведении в новом каталоге `finalize` запускается после `train`, чтобы взять те же модели, которые победили на валидации случайных схем.

Дополнительный [эксперимент с весами](results/peak_weight_metrics.csv) из раздела «Зоны роста» можно повторить командой `uv run --project lshvetsov --locked --python 3.12 -m lshvetsov.experiments.peak_weights`.

## Форма прогноза

После команды `finalize` запустите Streamlit из корня репозитория.

```bash
uv run --project lshvetsov --locked --python 3.12 -m streamlit run lshvetsov/streamlit_app/app.py --server.address 127.0.0.1
```

В [локальной форме](http://127.0.0.1:8501) выберите схему и сценарий, укажите дату и час по Сеулу, праздник и статус проката. Видимость вводится в километрах и переводится в единицы CSV. При закрытии форма скрывает погоду и возвращает 0. Карточка показывает валидационную RMSE и тестовые RMSE, MAE, R² и Peak RMSE выбранной модели. Ошибки погодных моделей измерены с фактической погодой из CSV.
