Цель исследования

Спрогнозировать число аренд велосипедов за конкретный час в Сеуле по сведениям, доступным на момент прогноза. Такая оценка помогает заранее увидеть часы с повышенным спросом и планировать доступность велосипедов в прокате.

Результат

Выбрали $winner_count моделей — по одной на каждый сценарий в каждой схеме. Валидационная RMSE определила победителей. Затем оценили каждого победителя на отложенных часах его схемы. Модели и метрики

Методология

Для прогноза перебираем сочетания сценариев, схем разделения и конфигураций. Источник данных — почасовые наблюдения в Сеуле с декабря 2017 по ноябрь 2018 года.

Обработка данных

ДанныеЧто делаем
ВремяОбъединяем дату и час по времени Сеула, сортируем строки и проверяем непрерывность часовой шкалы.
Спрос и статус прокатаРазделяем данные, обучаем модели и считаем ошибки на открытых часах. Прогнозируем число аренд за час.
Календарные признакиКодируем час, день недели и час выходного через one-hot. Для будней у признака «час выходного» отдельное значение. Праздник кодируем двоичным признаком, годовой цикл — синусом и косинусом дня года.
Погодные признакиПроверяем с фактической погодой из CSV. Дождь измеряем в миллиметрах. Точку росы исключили из-за её связи с температурой и влажностью.
ПредобработкаПо обучающей части определяем категории one-hot, средние и масштабы погодных признаков. Применяем эти преобразования в валидации и тесте.
ПрогнозОграничиваем отрицательные значения нулём. При закрытии возвращаем 0. Метрики считаем до округления.

Метрики

МетрикаЧто измеряетКак используем
RMSEКорень из средней квадратичной ошибки, в арендах за час. Крупные промахи влияют сильнее.Выбираем победителя по валидации, затем измеряем его ошибку на тесте.
MAEСреднее абсолютное отклонение от факта, в арендах за час.Показывает средний размер промаха.
R²Качество относительно прогноза по среднему. Чем выше значение, тем лучше.Оцениваем, какую долю разброса спроса объясняет модель.
Peak RMSERMSE на верхних 10% открытых часов по фактическому спросу.Разбираем ошибки на пиках.

Как обучаем и выбираем победителя

ЭтапСлучайные схемыВременные фолды
1. Обучаем конфигурацииКаждую конфигурацию обучаем на зафиксированных 80%.Каждую конфигурацию обучаем с нуля перед каждым валидационным окном.
2. Выбираем победителяДля каждого сценария выбираем модель с минимальной RMSE на валидационных 10%.Для каждого сценария выбираем настройки с минимальной RMSE по объединённым валидационным прогнозам.
3. Готовим модель к тестуБерём уже обученную модель-победителя.С выбранными настройками обучаем модель на всей истории до теста внутри той же схемы.
4. Измеряем итоговую ошибкуПроверяем победителя на тестовых 10% этой схемы.Проверяем победителя на заранее отложенных последних 10% открытых часов.

Оценка ретроспективная. Год наблюдений уже использовали для выбора моделей и разбора ошибок.
