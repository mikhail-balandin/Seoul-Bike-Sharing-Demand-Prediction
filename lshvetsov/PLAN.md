# План исследования прогноза велопроката

## Цель

Прогнозировать число аренд за час в Сеуле и измерить, насколько погодные данные улучшают прогноз по календарю и качество в пиковые часы. Выбрать по одной модели для каждого набора входов и показать их в Streamlit.

## 1. Данные и признаки

- Использовать [SeoulBikeData.csv](../SeoulBikeData.csv). Объединить дату и час в метку времени `Asia/Seoul`. Таргет — `Rented Bike Count`.
- Для обучения и оценки использовать открытые часы. Для известного закрытия в форме возвращать ноль.
- Включить час, день недели, праздник, взаимодействие часа с выходным и синус и косинус дня года. Применять одинаковое построение признаков при обучении и прогнозе.
- Кодировать календарные категории и стандартизировать числовые погодные признаки внутри обучающего пайплайна. В исторической погодной проверке использовать фактическую погоду.

| Набор входов | Признаки |
|---|---|
| Календарь | Час, день недели, час выходного, годовой цикл, праздник |
| Календарь + основная погода | Календарь, температура, ветер, видимость, дождь |
| Календарь + вся погода | Основной набор, влажность, солнечная радиация, снег |

## 2. Схемы проверки и конфигурации

| Схема | Обучение | Проверка |
|---|---|---|
| Временные фолды | Для каждого фолда вся история до начала проверяемого месяца | Июль, август, сентябрь и октябрь 2018 года по очереди |
| 80/20 внутри месяца | Первые 80% часов каждого месяца по октябрь, объединённые в обучение | Открытые часы из последних 20% каждого месяца |
| Случайное 80/20 | 80% открытых часов по октябрь после перемешивания с `random_state=42` | Оставшиеся 20% открытых часов |
| Весь ноябрь | Все открытые часы с декабря 2017 по октябрь 2018 года | Одни и те же открытые часы ноября для всех кандидатов |

- Базовый ориентир — медиана по часу и типу дня. Линейная регрессия со свободным членом, Ridge и Lasso с α 0,1 / 1 / 10 / 100 проверяются во всех трёх сценариях.
- Во всех трёх сценариях проверяем прямой бустинг и коррекцию почасовой медианы бустингом. Для обоих вариантов используем сетку из восьми комбинаций. Итерации 180 / 200, максимум листьев 24 / 31 и скорость обучения 0,05 / 0,10. Минимум 20 наблюдений в листе, ранняя остановка отключена, seed 42.
- Ошибки считаем до округления прогноза. Сравниваем RMSE, MAE, R² и Peak RMSE для верхних 10% часов по наблюдаемому спросу.

## 3. Выбор моделей

1. В каждой из трёх схем до ноября выбираем минимальную RMSE отдельно для каждого семейства и набора входов. Итоговая RMSE фолдов считается по объединённым прогнозам.
2. Объединяем совпавших кандидатов и сохраняем их схемы отбора. Каждый кандидат переобучается на всей истории до ноября.
3. Для каждого сценария выбираем наименьшую RMSE на общих ноябрьских часах и сохраняем модель для Streamlit. Для независимой оценки победителей нужен следующий период.

В отчёте показываем три семейства с наименьшей ноябрьской RMSE на сценарий. Все сравнения по RMSE и Peak RMSE сохраняем в подробных замерах.

## 4. Отчёт и форма

- HTML содержит цель исследования, результат по каждой модели, методологию и данные. В результате показать схему отбора, модель, гиперпараметры и все ноябрьские метрики.
- В разделе «Данные» выделить финалистов, зоны роста и все исследования. Рядом с таблицей финалистов показать факт и прогнозы за неделю и сравнить общую RMSE с ошибкой на пиках. В подробных таблицах сохранить все попытки, схемы и параметры.
- В Streamlit сохранить три варианта набора входов. Для выбранного набора запрашивать необходимые погодные поля. Рядом с прогнозом показывать конфигурацию, схему её отбора и ноябрьскую RMSE. При закрытии возвращать ноль.
- Проверить хронологию, отсутствие пересечений выборок внутри каждого прогона, совпадение метрик в HTML и CSV, ввод для трёх сценариев и правило закрытия.
